# den-kit collaboration rules

## Language

den-kit is an open-source project. Write all repository content and GitHub
collaboration in English, including README and documentation, code comments,
examples and UI copy, test descriptions and fixtures, commit messages, pull
request titles and descriptions, and issue and review comments.

Do not write Japanese in these artifacts. Communicate with Yuichi in Japanese.

## Public documentation

Write public documentation for users and contributors who cannot access private
tools or internal conversations. Keep private tracker identifiers, planning
milestones, assignments, acceptance status, and internal verification records
in Linear or Notion rather than README or public project descriptions.

Describe current behavior, reproducible setup, prerequisites, known limitations,
and contribution steps. Link to accessible repository files or public
documentation when a reference is needed.

Pull request descriptions should explain the code changes, relevant validation,
and technical limitations needed for review without private planning or personal
acceptance states.

## Product UI

Write ordinary app screens for people making instruments and effects. Include
information that helps them perform a task, choose an option, recover from an
error, or understand relevant data handling.

Keep operator billing and ownership, provider credentials, protocol plumbing,
and comparison controls out of ordinary product screens. Necessary technical
details belong in developer documentation or explicitly labeled diagnostics.
